# Correcciones de checkout, sesiones y controles

El checkout reserva inventario y usos de cupones antes de entregar el enlace
de Wompi. Las reservas duran 15 minutos y tambien se descuentan del inventario
disponible para la taquilla. Los pagos confirmados que llegan sin cupo se
registran como `paid_unfulfilled`, se muestran al comprador sin pedir otro pago
y notifican al organizador para conciliar la entrada o gestionar un reembolso.
El precio historico de la boleta refleja el importe pagado.

La sesion web pasa a cookie HttpOnly, Secure en produccion y SameSite=Lax,
con comprobacion de Origin para cambios autenticados. Las sesiones anteriores
se migran al consultar `/auth/me`; los clientes API mantienen soporte Bearer.
Un error temporal conserva la credencial y permite reintentar. El canje de una
invitacion actualiza tambien el estado React para abrir el panel directamente.

El linter de diseno se incluye con version y licencia MIT; ya no da exito al
faltar una skill local. Se corrigen falsos positivos de comentarios, resets,
foco accesible y controles nativos, con pruebas de regresion. Se reducen los
presupuestos existentes de diseno (556 a 538) y CSS (41 a 40), sin elevarlos.
En CI, la indisponibilidad de la base de pruebas ahora es un fallo obligatorio.

## Validacion

- Suite completa de backend: 590 aprobadas, una omision prevista por la
  constraint que impide crear un username con arroba. Ejecucion en cuatro
  bases PostgreSQL 17 locales aisladas, con las pruebas existentes sin desactivar.
- Incluye carrera por el ultimo cupo, reserva de cupon, liberacion tras fallo
  del proveedor, vencimiento y conciliacion de pago tardio, cookie/CSRF,
  permisos y coherencia entre esquema y migraciones.
- Pruebas seleccionadas en Chromium: compra, login, onboarding, puerta,
  creacion de evento, aceptacion legal, recuperacion de sesion e invitacion.
- Build, auditoria npm de produccion, lint CSS y gate de diseno verificados.
- Wompi se simula en pruebas; no se realizan cobros reales.

## Despliegue y recuperacion

Aplicar `db/migrations/044_checkout_reservations.sql` antes del codigo nuevo.
La migracion agrega dos columnas, indices y reemplaza funciones de forma
transaccional. No elimina pagos ni boletas existentes. El esquema consolidado
incluye los mismos cuerpos SQL y la lista de despliegue incluye la migracion.

Comprobar `/api/health` con `status=ok` y `schema=ok`, pagina publica y acceso
del staff. Si hay regresion, restaurar el deployment anterior de Vercel;
conservar la migracion 044, compatible con el codigo anterior, para seguir
protegiendo las reservas que ya existan. Los pagos `paid_unfulfilled` necesitan
conciliacion humana; este cambio no ejecuta reembolsos bancarios automaticos.
